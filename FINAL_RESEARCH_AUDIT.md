## Second-pass additions (this update)
Responding to a direct request to close remaining gaps and "overcome
failures," this session:
1. Wired real benchmark data into the PQC recommendation engine for the
   first time (closing a real Section 24 input gap), verified by 2 new tests.
2. Built and ran the 3 remaining Section-40 ablation types (AI model,
   explainability layer, PQC benchmark information) — previously only
   feature ablation existed.
3. **Caught and fixed a real bug twice**: two ablation scripts joined
   results across separate temporary databases by `Asset.id` (a random
   UUID, not stable across runs), silently producing false "0 changes"
   results. Found by noticing an inconsistent secondary number, fixed by
   joining on `hostname` instead, with an assertion guarding recurrence.
4. Added statistical significance testing (paired bootstrap + permutation
   tests), which overturned a point-estimate impression: XGBoost's
   apparent edge over the rule baseline is **not** statistically
   significant (p=0.659).
5. Verified the PostgreSQL deployment path for real (migrations + full
   demo pipeline against a live `docker-compose` Postgres instance),
   **catching and fixing a real `VARCHAR(32)`-too-narrow bug** that SQLite
   had silently tolerated. Added a dedicated CI job so this is now
   continuously verified, not a one-off check.
6. Captured 15 real, visually-verified screenshots of the running
   frontend against live, populated data — finding and fixing a real
   Recharts headless-rendering race along the way.
7. **A Docker image build filled the host disk to near-zero free space**,
   breaking `qiskit_aer` imports until space was freed. This was surfaced
   directly rather than worked around by guessing at deletions in
   directories outside this project's scope (likely a separate WSL
   installation). The full `docker-compose up` stack (built backend/
   frontend images, not just the pulled `postgres` service) remains
   unverified as a direct consequence — recorded honestly rather than
   silently claimed as done.

## Fourth-pass additions (this update)
Responding to a direct request to review production readiness and close
any remaining gaps, this session:
1. Closed a real gap the third pass's own threat model had documented but
   not fixed: `docker-compose.yml` shipped a fallback `QS_SECRET_KEY`
   identical to the one hard-coded in `app/core/config.py`, so an operator
   who forgot to set it would silently get a container signing every JWT
   with a secret published in this repository's own source. `Settings` now
   refuses to start outside `environment=development` while the secret is
   still that default (`app/core/config.py::_reject_insecure_defaults_outside_development`,
   `tests/test_config.py`, 3 new tests), and the compose file's fallback was
   removed in favor of a hard `${QS_SECRET_KEY:?...}` failure.
2. Fixed a username-enumeration timing side-channel in `/auth/token`:
   `verify_password` (bcrypt, deliberately slow) previously only ran when
   the username existed, so a nonexistent-username request returned
   measurably faster than a wrong-password one. It now always runs against
   a real hash — a fixed dummy hash for the not-found case
   (`app/core/security.py::_DUMMY_PASSWORD_HASH`) — covered by 1 new test.
3. Hardened the backend Docker image: runs as a non-root user, adds a
   `HEALTHCHECK` against `/api/v1/health`, and a new
   `docker-entrypoint.sh` applies pending Alembic migrations before the API
   starts (previously a fresh `docker-compose up` against an empty
   PostgreSQL database would 500 on every request until someone ran
   migrations manually). `frontend`/`prometheus`/`grafana` in
   `docker-compose.yml` now wait on the backend's healthcheck rather than
   just its process start.
4. Fixed a real (pre-existing, not introduced this session) `ruff` finding
   in `app/ai/explain.py` (`UP038`) that the "ruff check: clean" claim had
   not actually held against — the pinned `ruff==0.8.4` was never
   previously re-run against this exact file/rule combination in a clean
   environment. `ruff check app` is now genuinely clean, re-verified in a
   fresh install of the pinned `requirements.txt`.
5. Re-verified the full 76-test backend suite and the frontend
   `tsc -b && vite build` in a clean dependency install (not from memory of
   a prior green run) — this is also what caught item 4.
6. Retheme of the dashboard (light/paper palette replacing the previous
   dark theme) and all 15 `docs/screenshots/*.png` regenerated against it;
   no functional/API change.

## What "complete" means for this project, honestly
Every core pipeline (discover → classify → assess → recommend → plan →
simulate) runs end-to-end on real, if synthetic, data, with a passing test
suite, all four Section-40 ablation types executed, statistical
significance testing applied to the headline AI-vs-rule comparison, the
PostgreSQL deployment path verified against a real instance (catching a
real bug), and real screenshots of a genuinely working frontend. Results
that went against the initial hypothesis (XGBoost not winning, and not
even statistically distinguishable from the rule baseline; a noise feature
turning out to be pure noise; two ablation scripts' first drafts being
silently broken) are reported as found, not adjusted. What remains
incomplete, honestly: real quantum hardware execution (by design — no
credentials exist), the full built-image `docker-compose up` stack
(interrupted by a host disk-space incident), hybrid signature composition,
and the pytest suite's own assertions running against Postgres directly
(only the demo pipeline has). See `docs/masters-application/14_limitations.md`
and `15_future_research.md` for the complete, current list.
